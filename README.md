# 日间手术预入院管理平台 · 演示原型（Demo）

> 本 Demo 为**功能演示原型**，按《日间手术预入院 Demo 开发任务单 v1.4》实现，用于投标文件配图与现场演示。
> **非生产系统**：不含真实患者数据、不对接真实 HIS、不做权限鉴权与数据加密，请勿用于实际诊疗业务。

---

## 1. 快速开始

```bash
# 环境：Node.js ≥ 18（推荐 20/22）
cd preop-demo-final
npm install
npm run dev          # http://127.0.0.1:5417
```

其它命令：

```bash
npm run build        # 产出 dist/（纯静态，可直接拷到任意静态服务器）
npm run preview      # http://127.0.0.1:4178 预览构建产物
```

- 建议浏览器窗口 **1440 × 900**（界面按此分辨率设计，无横向滚动条）。
- 演示数据保存在浏览器 `localStorage`，键名 `PREOP_DEMO_V2`；换浏览器/清缓存即回到初始种子数据。
- 左下角「演示数据 · 重置」可一键恢复初始状态（**这是界面里唯一会真正清空数据的地方**，仅用于演示复位）。

## 2. 技术栈与目录

| 项 | 说明 |
|---|---|
| 框架 | Vue 3（`<script setup>`）+ Vite 5 |
| UI | Element Plus 2.8（中文语言包）+ `@element-plus/icons-vue` |
| 路由 | vue-router 4，hash 模式（`#/workbench`） |
| 状态 | `reactive` 单一状态源（`src/store/state.js`），不引入 Pinia/Vuex |
| 日期 | dayjs，**全部相对今天生成**，任何时候打开都是「今天」 |
| 外部数据 | 只经 `src/api/his.js` 一个出口，`USE_MOCK = true` 时走本地模拟 |

```
src/
├─ api/his.js            # 外部系统唯一出口（申请单池 / 患者档案 / 检查报告）
├─ mock/                 # 模拟 HIS 与种子数据（字典、患者、账户、排程、日志…）
├─ store/                # 14 个模块，state.js 为唯一数据源，db.js 为统一出口
│  ├─ state.js           # 响应式状态 + 播种/持久化/重置
│  ├─ logs.js            # 操作日志：只追加，九要素，Object.freeze
│  ├─ accounts.js        # 储值金：缴存/冻结/转入住院/退出结算/冲正
│  ├─ schedules.js       # 排程：创建/调整（booked* 只读）/取消/冲突检测
│  └─ …
├─ utils/guard.js        # 患者状态机 + 角色权限矩阵（全站唯一流转校验）
├─ utils/audit.js        # 日志字段、差异比对、校验码
├─ components/           # PatientHeader / ScheduleCard / ExamList / ReportDrawer / PickPatient
├─ layout/               # 顶栏（医院标识 + 一级模块）、深色侧栏（按业务阶段分组）、nav.js 菜单配置
└─ views/                # 16 个页面
docs/screenshots/        # 投标用截图（见第 5 节）
```

## 4. 数据变更规则（现场交接最有用的一页）

1. **不提供删除**：界面里没有「删除」二字，业务数据一律不可物理删除。
2. **草稿可移除、可恢复**：费用草稿行「移除」后灰显保留，可用「显示已移除」查看并恢复。
3. **已提交只能作废**：费用单提交后只读，纠错走「作废」→ 灰显保留 → 可「重新录入」新单。
4. **流水只能冲正**：储值金流水不可改不可删，冲正时原记录灰显划线 + 生成一笔负数流水，`可用 + 冻结 + 住院 + 已消耗 = 缴存总额` 恒等式始终成立。
5. **全部操作留痕**：每次写操作都追加一条九要素日志（操作人 / 角色 / 时间 / 模块 · 页面 / 动作 / 对象 / 变更前 / 变更后 / 原因 / 结果），只追加、带序号与校验码，失败动作也记 `FAIL`。

另有三条硬约束：

- 患者状态只能按状态机流转（`APPLIED → DAY_SURGERY → SCHEDULED → ADMITTED → IN_SURGERY → 转归`），非法流转直接拒绝并提示。
- 排程的「预约五字段」（预约日期/手术间/台次/主刀/预约人）创建后**永不修改**，调整安排只改「实际安排」，两者差异在界面上并列显示。
- 外部数据只走 `api/his.js`，界面统一标注「演示数据源 · 本地模拟 HIS」+ 顶栏「演示环境」胶囊。

## 6. 演示脚本

### 6.1 主路径（约 6 分钟，默认走这条）

主角：**张建国 D2026001**（术前检查与评估都完成，等着排手术）。

| 时间 | 页面 | 操作 | 一句话 |
|---|---|---|---|
| 0:00 | 工作台 | 停在「手术未安排」页签，指一行 | 「日间中心的日常视图，按未安排/已安排/已完成分。这位张建国，检查和评估都做完了，等着排手术。」 |
| 0:20 | 工作台 | 点「创建预约」 | 「排手术要选日期、手术间、台次、主刀。」 |
| 0:30 | 手术排程 | 今天 · 日间 1 间 · 第 1 台 → 提交 | 「两项评估都通过才能排，排完自动给患者发预约成功短信。」 |
| 0:55 | 手术排程 | 切日视图 | 「手术室视角，三个间三个台次，一目了然。」 |
| 1:05 | 手术排程 | 点排程卡 → 把手术间改成日间 2 间 → **黄条跳出** | 「手术室临时换间——注意，系统立刻提示这个改动和患者预约的不一致。」 |
| 1:30 | 手术排程 | 选原因 → 保存并通知 | 「保存的同时发变更短信，原预约信息不覆盖，留着做对比。」 |
| 1:50 | 消息通知 | 指 3 条记录 | 「预约成功、入院前提醒、刚才的变更，状态和回执都在这。」 |
| 2:10 | 储值金 | 冻结储值金 | 「术前费用走专项储值金，先冻结，冻结后不能直接支取。」 |
| 2:30 | 入院登记 | 输入 D2026003 → 从 HIS 读取 | 「入院登记和 HIS 一体化，住院证、报告、储值金一起带过来。」 |
| 2:55 | 手术报到 | 模拟扫码 → 四项校验清单 | 「报到前查四件事：有预约、是今天、评估通过、钱到位。缺一样都不让报。」 |
| 3:20 | 手术报到 | 确认报到 | 「报到后状态转术中。」 |
| 3:35 | 手术费用 | 调入常用组套（8 条）→ 提交费用 | 「手术室补录费用，也可以调组套，一组 8 条带过来。」 |
| 4:05 | 手术医嘱 | 录入丙泊酚 → 添加 | 「医嘱必须有麻醉药，红色标签标出来。」 |
| 4:25 | 转普通入院 | 选原因 + 方式 → 提交 | 「术中发现要转普通住院，两项都必填，少一项提交不了。」 |
| 4:50 | 操作日志 | 展开「调整安排」那条 | 「刚才换手术间那一下：谁、几点、改前日间 3 间、改后日间 1 间、为什么改，全在这一行。」 |
| 5:15 | 患者轨迹 | 选张建国 | 「换个角度：7 天前接申请、6 天前建档缴存、5 天前出报告、4 天前过评估，今天排程。每一步都串得起来。」 |
| 5:45 | 工作台 | 切「手术已完成」页签 | 「整条链路走完了。」 |
| 5:55 | 收尾 | — | 「每一次改动都有记录，业务数据不提供删除。」 |

三个「刺点」（评审最容易记住的）：1:05 黄条实时出现（数据是活的）、2:10 冻结后不能支取（财务有约束）、2:55 四项校验（规则写进了代码）。

### 6.2 ▲ 专攻（约 2 分钟，评审只看评分点时用）

只用 5 个页面，每个 ▲ 一个动作：储值金冻结→转住院（A1）→ 入院登记读 HIS（A2）→ 转普通入院双必填（A3）→ 手术费用补录 + 组套（A4）→ 手术医嘱麻醉药（A5）。

### 6.3 极简（约 3 分钟，时间被压缩时用）

1. **流程能跑通**：工作台 → 手术排程日视图。
2. **规则管得住**：手术报到四项校验。
3. **数据追得到**：操作日志展开行 + 患者轨迹。

### 6.4 常见追问对照

| 评审会问 | 调出这个页面 |
|---|---|
| 「数据能不能删？」 | 费用单作废后灰显 + 重新录入；储值金冲正后划线 + 负数流水 |
| 「有没有留痕？」 | 操作日志展开行（字段级改前/改后） |
| 「能不能按患者追溯？」 | 患者轨迹时间轴 |
| 「基础数据全不全？」 | 收费项目与药品、费用常用组套 |
| 「跟 HIS 是真对接吗？」 | 入院登记页的「演示数据源 · 本地模拟 HIS」标识（我们如实标注为模拟） |

## 8. 已知边界（如实说明，避免演示被问住）

- 无后端：所有数据在浏览器内存 + `localStorage`，多人不同步、换机器不共享。
- HIS / LIS / PACS 均为**本地模拟**，接口在 `src/api/his.js` 预留了真实 HTTP 分支，页面无需改动。
- 权限为演示级（角色下拉切换 + 按钮级置灰），不含登录、单点登录、数据级授权。
- 统计报表、与既有医技系统的深度集成不在本 Demo 范围（对应任务单中「部分实现」的 3 项）。
- 界面左上角的医院名称直接取自 `src/layout/nav.js` 的 `HOSPITAL.name`（当前为「四川省骨科医院」）。如需脱敏版本，把该值改成一个中性的名称即可，顶栏、浏览器标题会同步更新，无需改其它文件。
