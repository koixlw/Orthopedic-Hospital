# 日间手术预入院管理平台 · 演示原型（Demo）

> 本 Demo 为**功能演示原型**，按《日间手术预入院 Demo 开发任务单 v1.4》实现，用于投标文件配图与现场演示。
> **非生产系统**：不含真实患者数据、不对接真实 HIS、不做权限鉴权与数据加密，请勿用于实际诊疗业务。

---

## 1. 快速开始

```bash
# 环境：Node.js ≥ 18（推荐 20/22）
cd preop-demo-final
npm install
npm run dev          # http://127.0.0.1:5417
```

其它命令：

```bash
npm run build        # 产出 dist/（纯静态，可直接拷到任意静态服务器）
npm run preview      # http://127.0.0.1:4178 预览构建产物
```

- 建议浏览器窗口 **1440 × 900**（界面按此分辨率设计，无横向滚动条）。
- 演示数据保存在浏览器 `localStorage`，键名 `PREOP_DEMO_V3`；换浏览器/清缓存即回到初始种子数据。
- 左下角「演示数据 · 重置」可一键恢复初始状态（**这是界面里唯一会真正清空数据的地方**，仅用于演示复位）。

## 2. 技术栈与目录

| 项 | 说明 |
|---|---|
| 框架 | Vue 3（`<script setup>`）+ Vite 5 |
| UI | Element Plus 2.8（中文语言包）+ `@element-plus/icons-vue` |
| 路由 | vue-router 4，hash 模式（`#/workbench`） |
| 状态 | `reactive` 单一状态源（`src/store/state.js`），不引入 Pinia/Vuex |
| 日期 | dayjs，**全部相对今天生成**，任何时候打开都是「今天」 |
| 外部数据 | 只经 `src/api/his.js` 一个出口，`USE_MOCK = true` 时走本地模拟 |

```

│  ├─ state.js           # 响应式状态 + 播种/持久化/重置

│  ├─ accounts.js        # 储值金：缴存/冻结/转入住院/退出结算/冲正
│  ├─ schedules.js       # 排程：创建/调整（booked* 只读）/取消/冲突检测

├─ components/           # PatientHeader / ScheduleCard / ExamList / ReportDrawer / PickPatient

docs/screenshots/        # 投标用截图（见第 5 节）
```

| 系统管理员 | 李伟 / A0001 | 字典维护、日志与轨迹查看、演示数据重置 | 全部 16 项 | 全权限（演示需要，见下文第 4 条） |

**储值金为什么四个人看到的不一样**（对照《开发任务单》功能—角色矩阵）：

| 动作 | 功能编号 | 收费员 | 护士 | 医生 |
|---|---|---|---|---|
| 缴存专项储值金 | FUNC-DEP-001 | ✅ | — | — |
| 冻结储值金 ▲ | FUNC-DEP-002 | ✅ | — | — |
| 转入住院储值金 ▲ | FUNC-DEP-003 | — | ✅ | — |
| 退出日间手术并门诊结算 ▲ | FUNC-DEP-004 | ✅ | ✅ | — |
| 冲正缴存记录 | FUNC-DEP-006 | ✅ | — | — |
| 查询账户与流水 | FUNC-DEP-005/007 | ✅ | ✅ | —（无菜单） |

一句话：**钱箱动作（缴存、冻结、冲正）只归收费员；护士只做「转入住院储值金」和「退出结算」**——因为转入发生在护士办的入院登记环节，冻结是财务动作。权限码表 `utils/guard.js` 的 `GRANTS` 里每个码后面都标了来源 FUNC 编号，方便逐条核对。

**权限的三层实现（与 4.2 四条约定一一对应）**

1. **界面层：无权限的菜单与按钮一律隐藏，不置灰。** 侧栏整组为空时连分组标题一起隐藏，左下角提示「当前岗位仅显示有权限的菜单」；`侧栏 → nav.js` 的 `perm`、路由 `meta.perm`、按钮 `can('动作码')` 共用同一份权限码表（`utils/guard.js`）。
2. **路由层：** 手工改地址栏访问越权页面，会被守卫拦回工作台并提示「当前角色（护士）无『操作日志』访问权限」。
3. **接口层：** 每个写操作入口先调 `assertCan('动作码')`，不通过则**写一条 `result=FAIL` 的日志再抛错**，页面提示同一句话。日志里动作记为 `权限拦截`、对象是被拦的动作、失败原因是可读中文，例如「当前角色（医生）无权执行冻结储值金」——不是 `permission denied`。
   - 演示：用医生账号登录后，在浏览器控制台直接调 `accounts.freeze('P001')`，接口层照样拒绝并写 FAIL 日志——按钮藏起来只是界面层，函数里还有一道。
4. **管理员全绿是演示需要，不是设计缺陷。** 演示环境的管理员拥有全部操作权限，正式系统按岗位分离；这条说明同时写在「系统参数 → 角色与权限」页与本节。

> 岗位差异最直观的一处：储值金页面。**收费员**看到「缴存 / 冻结 / 退出结算」，**护士**看到「转入住院储值金 / 退出结算」，**医生**看不到储值金菜单。

### 3.3 短信通知与模板（对应招标第 6、7、10 项）

页面：**消息通知**（`/msg`），三个页签——预约通知 / 入院前通知 / 全部记录。

| 通知 | 触发时机 | 默认行为 | 套用模板 |
|---|---|---|---|
| 预约成功 | 创建手术预约（预约完成）时 | 立即自动发送，可在参数页关闭 | 手术预约成功通知 |
| 入院前提醒 | 手术日前 N 天 09:00（N 默认 1，1—7 可调） | 到点自动发送；页面上可「立即执行通知任务」补发 | 入院前提醒通知 |
| 安排变动 | 实际安排与预约不一致时 | 按参数走短信 / 电话 / 两者 | 手术安排变动通知 |

**模板可自定义**：每个通知各有独立模板，正文用 `{患者姓名}`、`{手术日期}`、`{星期}`、`{手术间}`、`{台次}`、`{主刀}`、`{麻醉方式}`、`{禁食提示}` 等 17 个变量占位，发送时按患者与排程实时替换。入口就在通知页右上「短信模板配置」，或每张预览卡右上「编辑模板」——不用跳到系统参数页。

- **编辑**：选模板 → 点上方变量插入到光标处 → 改正文 → 下方实时预览（按示例患者渲染）→ 保存并生效；随时可「恢复默认」。
- **校验**：必须含 `{患者姓名}`；只允许已列出的变量；≤ 300 字，页面按 70 字/条提示计费条数。不通过时提示中文原因，例如「存在未知变量：{不存在的变量}」。
- **留痕**：每次保存写一条 `UPDATE` 日志（对象＝模板名，变更前后都是全文），版本号 +1，记录修改人与时间。
- **权限**：编辑模板属配置动作，只有管理员有 `msg.tpl`；其他岗位连按钮都看不到（不置灰），接口层 `assertCan` 同样拦截。

> 通知记录本身仍然「只能由业务动作产生」：页面没有新建短信、也不能改某一条已发出的通知——可编辑的是**模板**，不是通知。历史记录仍按当时的内容留存，改模板只影响之后的发送。

## 4. 数据变更规则（现场交接最有用的一页）

1. **不提供删除**：界面里没有「删除」二字，业务数据一律不可物理删除。
2. **草稿可移除、可恢复**：费用草稿行「移除」后灰显保留，可用「显示已移除」查看并恢复。
3. **已提交只能作废**：费用单提交后只读，纠错走「作废」→ 灰显保留 → 可「重新录入」新单。
4. **流水只能冲正**：储值金流水不可改不可删，冲正时原记录灰显划线 + 生成一笔负数流水，`可用 + 冻结 + 住院 + 已消耗 = 缴存总额` 恒等式始终成立。
5. **全部操作留痕**：每次写操作都追加一条九要素日志（操作人 / 角色 / 时间 / 模块 · 页面 / 动作 / 对象 / 变更前 / 变更后 / 原因 / 结果），只追加、带序号与校验码，失败动作也记 `FAIL`。

另有三条硬约束：

- 患者状态只能按状态机流转（`APPLIED → DAY_SURGERY → SCHEDULED → ADMITTED → IN_SURGERY → 转归`），非法流转直接拒绝并提示。
- 排程的「预约五字段」（预约日期/手术间/台次/主刀/预约人）创建后**永不修改**，调整安排只改「实际安排」，两者差异在界面上并列显示。
- 外部数据只走 `api/his.js`，界面统一标注「演示数据源 · 本地模拟 HIS」+ 顶栏「演示环境」胶囊。

### 6.1 主路径（约 6 分钟，默认走这条）

主角：**张建国 D2026001**（术前检查与评估都完成，等着排手术）。

| 时间 | 页面 | 操作 | 一句话 |
|---|---|---|---|
| 0:00 | 工作台 | 停在「手术未安排」页签，指一行 | 「日间中心的日常视图，按未安排/已安排/已完成分。这位张建国，检查和评估都做完了，等着排手术。」 |
| 0:20 | 工作台 | 点「创建预约」 | 「排手术要选日期、手术间、台次、主刀。」 |
| 0:30 | 手术排程 | 今天 · 日间 1 间 · 第 1 台 → 提交 | 「两项评估都通过才能排，排完自动给患者发预约成功短信。」 |
| 0:55 | 手术排程 | 切日视图 | 「手术室视角，三个间三个台次，一目了然。」 |
| 1:05 | 手术排程 | 点排程卡 → 把手术间改成日间 2 间 → **黄条跳出** | 「手术室临时换间——注意，系统立刻提示这个改动和患者预约的不一致。」 |
| 1:30 | 手术排程 | 选原因 → 保存并通知 | 「保存的同时发变更短信，原预约信息不覆盖，留着做对比。」 |

### 6.2 ▲ 专攻（约 2 分钟，评审只看评分点时用）

只用 5 个页面，每个 ▲ 一个动作：储值金冻结→转住院（A1）→ 入院登记读 HIS（A2）→ 转普通入院双必填（A3）→ 手术费用补录 + 组套（A4）→ 手术医嘱麻醉药（A5）。

**穿插 40 秒：短信模板能不能改？** 消息通知 → 预约通知 → 点卡片右上「编辑模板」→ 选一个变量插进正文（比如把「请致电 028-8888 6120」换成 `{联系电话}`）→ 下方实时预览跟着变 → 保存并生效 → 回操作日志筛「通知模板」，能看到改前改后的全文和修改人。

### 6.3 极简（约 3 分钟，时间被压缩时用）

1. **流程能跑通**：工作台 → 手术排程日视图。
2. **规则管得住**：手术报到四项校验。
3. **数据追得到**：操作日志展开行 + 患者轨迹。

## 8. 已知边界（如实说明，避免演示被问住）

- 无后端：所有数据在浏览器内存 + `localStorage`，多人不同步、换机器不共享。
- HIS / LIS / PACS 均为**本地模拟**，接口在 `src/api/his.js` 预留了真实 HTTP 分支，页面无需改动。
- 登录为演示级：选岗位即登录，不校验密码、无单点登录与数据级授权；正式系统对接院内统一认证，权限模型（页面 / 动作两级）可直接复用。
- 统计报表、与既有医技系统的深度集成不在本 Demo 范围（对应任务单中「部分实现」的 3 项）。
- 短信为模拟发送：模板与变量渲染是真的，但不接运营商网关；正式系统需把模板提交网关报备（报备号在参数里维护），报备通过后才能下发，本 Demo 未做报备流程。
- 界面左上角的医院名称直接取自 `src/layout/nav.js` 的 `HOSPITAL.name`（当前为「四川省骨科医院」）。如需脱敏版本，把该值改成一个中性的名称即可，顶栏、浏览器标题会同步更新，无需改其它文件。
